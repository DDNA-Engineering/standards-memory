# StandardsForge reference architecture

Document `SM-ARCH-001`, version `0.1.0-design`, is a proposed reference design. The local architecture below is implemented and qualified within the stated limits; the proposal is not an owner-approved product baseline.

## Position

The core is a framework-light Python library. Canonical data-only packs and preserved sources carry evidence; SQLite stores installed snapshots, local grants, and rebuildable external-content lexical indexes. The core does not import host applications. Querying never invokes a generation model.

Source acquisition, ingestion, and query paths are separate:

```text
official publisher source -> local ignored source directory -> offline manifest verification
verified PDF -> deterministic compiler -> preserved PDF + extracted text + fidelity report -> local pack
verified page-text pack -> deterministic outline compiler -> exact-span automated candidates + unsupported regions -> separate derived-structure pack
verified PDF + reviewed annotations -> structural compiler -> stable nodes + optional reviewed exact-span semantics + typed source-spanned relationships -> local pack
operator policy + local pack -> validation -> immutable object store -> atomic SQLite install
principal + explicit selector -> authorization -> snapshot-pinned batched dependency closure -> request-local page/node/relationship span re-verification -> detailed, compact, or concise evidence packet
caller-authored candidate + authorized detailed packet -> deterministic source-first static reader + neutral manifest-bound handoff
```

The source repository carries source metadata and verification code, not third-party PDF bytes. A separate synthetic starter contains only the two tracked fictional packs, their exact trusted policy, the verified core wheel and provenance, and stdlib-only setup and launcher code. Its deterministic stored ZIP is rebuilt twice, reopened against a closed manifest, and exercised from a path containing spaces without checkout imports. Setup validates all immutable files before writes, uses local dependency-free wheel installation, accepts only setup-owned partial state, and records a closed receipt only after full doctor, discovery, and exact-context smokes. Every rerun repeats validation and smokes. The starter does not qualify real-document behavior.

The separate prepared distribution may carry verified compiled packs containing only components classified by the recorded publisher metadata as Distribution Statement A. It also carries the exact acquisition manifest pinned by the corpus index, a schema-validated source baseline, and schema-validated wheel-build provenance. The release wheel is built twice from copied and inventoried inputs under a fixed epoch using an exact hash-locked backend artifact with index access and build isolation disabled, compared byte-for-byte, installed in a fresh environment, and only then retained. The provenance distinguishes wheel source inputs from the dependency lock used as release metadata. The distribution builder verifies that wheel, its source inventory, the fixed outer archive identity, and every final inventory/provenance digest; first-run setup repeats bundle checks before installation. Existing pack archive timestamps and package digests remain unchanged. Acquisition and compilation are explicit maintainer actions. Query code does not download or synchronize documents, and publisher currentness is not project approval.

Prepared corpus delivery and optional MCP code delivery remain separate. The GitHub prepared archive installs its bundled dependency-free core wheel and corpus offline on the declared Windows, Linux, and macOS profiles. Its Windows x64 CPython 3.12 profile additionally carries a closed, hash-inventoried MCP wheelhouse for a fully offline stdio installation. POSIX MCP is installed explicitly from the separate PyPI code channel and is pointed at the distribution-local database and object store; PyPI artifacts do not bundle or fetch standards content. Query execution remains local and network-free in both profiles.

Release-evidence sidecars avoid self-digest cycles in outer archives. Separate CycloneDX 1.7 documents describe the dependency-free wheel and starter-to-wheel graph. Separate unsigned in-toto Statement v1 documents use the SLSA provenance v1 predicate shape to bind subjects, resolved inputs, byproducts, builder versions, and source-control state. The closed evidence index inventories those four documents and the verification policy. Its offline verifier never fetches a URL and reports integrity, source-inventory, exact-commit, signature, and authenticity outcomes separately. The local statements always deny signatures and identity verification. A distinct protected-main CI job, unavailable to pull requests, rebuilds after the platform matrix and invokes an immutable pinned GitHub action to create signed SBOM attestations.

## Authority and identity

The source file is the preserved evidence. Records are extracted representations. A package digest identifies inventoried bytes, an edition ID identifies technical composition, a representation identifies page text, automated derived structure, reviewed structure, or curated records, and a document-family ID identifies a publisher-scoped family. They are never interchangeable. Resolution never chooses silently among multiple authorized representations; the package digest remains the authoritative read pin.

Rights statements inside a pack are provenance only. Operational authorization comes from a separate local policy, is persisted as a digest-bound grant, and is checked immediately before every query result. Withdrawal can disable access without changing evidence bytes.

## Implemented modules

- `pack`: strict data-only inventory, content, citation, and dependency validation.
- `policy`: trusted operator policy parsing and install authorization.
- `store`: SQLite snapshot metadata, grants, records, and FTS5 projection.
- `service`: all seven read operations, signed policy-bound continuations, and separate install/revoke administration.
- `cli`: separate administrative and read-only query commands.
- `mcp_server`: local stdio adapter exposing exactly the seven declared read operations under a startup-bound principal, with no administration, listener, or telemetry middleware.
- `source_catalog`: strict metadata validation and offline integrity verification for a closed local PDF source set.
- `compiler`: strict PDF text-layer extraction into page records, with raw PDF preservation, extracted-text sidecars, and explicit fidelity dimensions.
- `corpus_compiler`: Distribution Statement A-gated DLA acquisition composition, deterministic record-scoped unclassified page packs, composition-and-provenance-validated restartable archives, exact local policy generation, and policy-bound batch installation with obsolete-grant reconciliation.
- `outline_compiler`: deterministic exact-span method, clause, list, note, and caption candidates from verified page records, with ambiguous and unmatched content retained as unsupported regions and no automatic obligation or approval claim.
- `outline_review`: one-candidate, exact-package-bound unreviewed draft export and separate content-bound reviewer decision; global outline sidecar offsets are rebased to the same verified page text without a new PDF rendering. It does not infer semantics, links, or document-wide coverage.
- `structure_compiler`: reviewed structural nodes, bounded optional semantic decompositions, content-bound review events, and typed relationships bound to exact verified PDF/page-text spans, including explicit same-procedure step ordering.
- `query_cache`: bounded versioned in-process closure and search projections with checksum-verified envelopes; authorization decisions and source verification are never cached.
- `benchmark`: content-bound offline synthetic qualification, raw cold/warm response capture, executable assertion and metric arithmetic, and explicit separation from real-document quality claims.
- `doctor`: non-mutating runtime, schema, object-store, policy/grant, package-integrity, MCP-availability, and exact-query readiness diagnostics over an explicitly selected existing store.
- `prepared distribution`: an inventoried core wheel, portable offline core setup and root-anchored CLI launchers, plus a Windows x64 CPython 3.12 offline MCP dependency wheelhouse and stdio acceptance. POSIX MCP uses a separate explicit PyPI code install against distribution-local state; core setup has no package-index fallback.
- `build_starter_distribution`: exact-source wheel/provenance verification, policy and fictional-pack qualification, deterministic closed ZIP construction, and archive revalidation for portable onboarding.
- `release_evidence`: deterministic wheel/starter SBOM and unsigned statement generation, closed sidecar activation, and offline digest/source/commit verification; authenticated signature verification remains an external GitHub CLI trust-policy step.
- `handoff`: closed caller-authored candidate validation, canonical local evidence locator, detailed packet and rights-provenance binding, deterministic no-script HTML rendering, final reauthorization, and manifest-last no-overwrite bundle activation.

New page packs use records schema 0.2: portable records retain the exact sidecar path, digest, half-open UTF-8 offsets, and quote digest but do not repeat the text bytes. Validation reconstructs the in-memory record text from the verified slice before installation. Records 0.1 remains accepted for existing and structural packs. Deterministic Deflate archives are transport only and are unpacked into the same verified installed representation.

The FTS5 table is an external-content projection over `records`; transactional triggers and schema migration rebuild it from authoritative stored rows. It therefore stores index data but not a second full content table.

One synthetic acceptance packet qualifies reviewed semantic decomposition of a multi-page obligation and retrieval of its declared governing note, definition, table footnote, row, and header. It does not qualify document-wide semantic clause segmentation, automated dependency derivation, corpus-wide obligation classification, applicability, compliance, or human approval. The source-first handoff renders one selected detailed evidence packet and its required context without scripts or network access; a corpus-wide interactive outline/PDF reader and rendered side-by-side editions remain outside the completed slices. OCR, figure-visual interpretation, optional semantic adapters, and additional local-host adapters also remain outside. Derived outlines are source-linked unreviewed navigation candidates, not semantic correctness or applicability claims. The full local corpus remains a source-linked physical-page representation unless a separate derived or reviewed pack is explicitly selected. A hosted shared-server profile is not planned; the local MCP adapter is a process boundary for a user-controlled installation.

Required closures are cached only as package-pinned record IDs and edges. Every request reloads current rows, re-reads and hashes each distinct source or sidecar once, and reauthorizes immediately before return. Search cache keys include corpus and authorization generations, the caller's active visibility fingerprint, exact filters, limit, and ranker version. Package installation/grant changes and revocation advance generations.

Verified bytes, resolved paths, and decoded UTF-8 text are shared only inside one request. Compiled page records and structural node/relationship evidence spans are checked against exact half-open UTF-8 byte offsets and quote digests. Multi-span logical text is reconstructed only by the declared newline join and is backed by a separately inventoried assembled sidecar; retrieval rechecks every contributing page fragment. Semantic statements, qualifiers, and quantities must occur in their cited structural spans, and their review event is bound to the record content digest. Reviewed procedure ordering is explicit: a `sequence_after` edge binds one list-item step to one earlier sibling under the same parent, is source-spanned, and retrieves the predecessor as required context. Legacy packs without page offsets retain the full-sidecar compatibility check. Structural validation requires its resolved required-edge projection to equal the retrieval dependency projection. Obligation pages expand one union closure and project the established per-obligation response shape; edition comparisons keep one verification context per package.

Edition comparison uses exact record IDs as its only authoritative cross-package identity. Unique unmatched kind and clause-reference pairs are content-hashed review candidates in a separate collection and cannot alter authoritative changes or edge deltas. Required-dependency impact traversal runs independently over the before and after graphs and emits side-qualified paths, preventing a path from combining edges from different editions. A physical source relocation with unchanged record and structural meaning is `moved`; other substantive changes remain `modified`. Reviewed mappings, split/merge alignment, fuzzy equivalence, and semantic change classification require a later content-addressed reviewed artifact.

`concise_evidence_v1` is an opt-in progressively expandable projection. It includes each exact evidence record once, merges governing relationship declarations, and interns sources, derivations, structure nodes, and spans into packet-local registries. It retains explicit authorization and coverage. Detailed JSON remains the compatibility default, and tokenizer measurements are reported only when a tokenizer is explicitly configured or an external benchmark names the encoding.

The MCP server defaults to `text_and_structured`, returning the existing JSON text and structured result. Trusted startup configuration can select `--result-mode structured_only` to omit the duplicate success text payload; tool callers cannot select the mode, and typed errors remain text results. Each tool publishes an operation-specific, self-contained success schema. The repository contract gate separately validates those envelopes and the detailed, compact, concise, continuation, and typed-error packet contracts with a CI-only schema dependency; the core read runtime remains dependency-free.

The benchmark runner is a source-checkout qualification tool with a CI-only schema dependency and is not invoked by core query paths. It validates a reviewed suite digest, exact fixture package identities, and trusted local policy independently; denies networking during installation and cases; installs once into a temporary store; then creates a fresh service instance for each cold in-process cache sample and repeats the same operation immediately for the warm sample. Canonical response bytes, case failures, release-gate counters, and metric arithmetic are recomputed before an artifact is accepted. Timing and byte observations are not cross-environment gates, and synthetic results cannot be relabeled as human-reviewed real-document quality.

All untrusted pypdf work is isolated behind `pdf-extraction-worker/0.1.0`. The parent verifies catalog/acquisition identity, creates a canonical request without output or machine paths in its digest, starts one blocked child per PDF, installs OS containment, then releases the child. POSIX workers apply address-space, CPU, file-size, and no-core limits and run in a killable process group. Windows workers are assigned to a Job Object with per-process/job committed-memory, process CPU, active-process count, and kill-on-close limits before reading the source. Failure to establish the platform controls is fatal.

The worker rechecks source size and SHA-256 after containment, validates exact parser versions, performs strict parsing and the declared encryption/extraction mode, enforces decompressed content and normalized UTF-8 bounds, and writes one canonical page file per physical page. The digest-bound `result.json` is the activation marker. The parent accepts only the exact regular-file set with no links or reparse points, validates every count, order, byte length, digest, UTF-8 value, aggregate limit, and protocol identity, then streams page files into the existing sidecars. Timeout kills and reaps the entire worker group or job. A parser exception, crash, resource violation, protocol mismatch, or partial result fails the component; corpus checkpointing records the stable failure and cannot issue a complete status. A valid empty text layer remains a separate `no_text` outcome.

MCP initialization supplies a concise MIL-STD reading protocol, and each tool carries an operation-specific interpretation boundary. The instructions route a model from exact resolution to package-pinned discovery and evidence retrieval, distinguish physical page text, automated derived structure, reviewed structure, and curated records, and prohibit converting normative wording or incomplete obligation enumeration into applicability or compliance claims. Clients that ignore MCP initialization still receive the critical boundary in each tool description and in returned coverage and derivation fields.

`write-pack-policy` is an administrative onboarding aid, not a query operation. It validates the pack, requires the operator to state the principal and expected content class, rejects a mismatch with the pack claim, and writes an exact one-pack allowlist. The subsequent install and all reads continue through the existing external-policy authorization boundary.

`doctor` is a CLI-only diagnostic, not a seventh query or MCP operation. It opens SQLite with `mode=ro` and `query_only`, never initializes or migrates state, validates the supplied trusted policy independently, and selects one policy-scoped authorized record for a real `get_clause` smoke through a read-only store. Quick mode validates that deterministic package while checking all stored object paths; full mode validates every installed package. The report cannot repair state or turn imported rights claims into authority.

`export-handoff` is an administrative local write composed over the existing detailed `get_clause` path, not a seventh query or MCP operation. The caller-authored candidate has its own closed provenance contract and cannot choose evidence references or decision states. The export includes the exact detailed packet, rights claims with no authorization effect, a canonical package/record locator that is not bearer authority, and fixed host-owned undecided states. It reauthorizes immediately before manifest-last activation. The HTML renderer escapes all source and candidate content, emits no active elements, and uses a restrictive content-security policy; retrieved document instructions remain untrusted evidence data.

Lexical discovery exposes `exact_phrase`, `all_terms`, `any_terms`, and opt-in `natural_language` modes; `all_terms` preserves the original default. Raw input, parsed count, and each term are bounded before FTS execution. The three compatibility modes quote every chunk against the `unicode61` index, so caller text never becomes raw FTS syntax. `natural_language` uses a separate `porter unicode61` index over headings and text, removes a fixed versioned set of question scaffolding, attempts stemmed AND, and only when that is empty attempts one stemmed OR fallback. The response discloses effective and ignored terms, tokenizer, row-local ranker, attempted strategies, and the selected strategy. Row-local scoring avoids global corpus statistics, so unauthorized rows cannot influence visible scores or ordering. Dots, slashes, and hyphens remain visible inside reported chunks even though SQLite may split them internally. Results include matched snippets, exact source citations, and structural root-to-parent ancestry when present. Exact identifier resolution remains a separate `list_documents` then `resolve_document` workflow with no hidden lexical, network, model, synonym, or scope-broadening fallback.
