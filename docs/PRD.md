# StandardsForge product baseline

Document `SM-PRD-001`, version `0.1.0-design`, is a proposed baseline derived from the supplied PRD. Product and release ownership remain unassigned.

The product compiles authorized technical documents into immutable, source-linked packs and returns the smallest sufficient evidence for a task while keeping exact edition, governing conditions, unresolved inputs, and completeness visible. Correct engineering-information work is the outcome; fast search or fluent prose alone is not success.

The standalone core owns source identities, exact citations, package validation, deterministic local retrieval, coverage accounting, and portable exports. Host systems own project baselines, applicability, decisions, and approvals. Public accessibility, processing permission, model permission, and redistribution permission are separate decisions.

The distribution model has three explicit artifacts. The source-only repository carries the compiler, contracts, and synthetic examples. The portable synthetic starter carries a twice-built verified core wheel, two exact fictional packs, their trusted policy, and stdlib-only setup and launcher scripts; its closed manifest and receipt bind every immutable input and every installed-state smoke, but it qualifies fictional contract behavior only. The separate prepared end-user release carries verified precompiled packs for the recorded public DLA baseline, the exact acquisition manifest pinned by the corpus, a machine-readable qualification of selection and coverage, and build provenance for the exact wheel. Release construction verifies the exact locked backend artifact, builds the wheel twice from an inventoried source copy without dependency-network access under a fixed epoch, requires byte identity and an isolated core smoke, and then binds that verified artifact into a deterministic outer ZIP. Deterministic sidecars bind the exact wheel and starter to CycloneDX SBOMs, unsigned in-toto/SLSA-shaped statements, source state, and dependency locks; offline verification proves digest consistency, while authenticated producer identity requires the separate protected-main CI attestation and trust-policy verification. Each distribution builder and first-run setup verify file inventories and provenance before trusting the bundle; setup then performs only local validation and indexing. Users of the prepared release do not reacquire or recompile that baseline. Publisher currentness does not establish a project's approved baseline. Each user still owns local state and authorization. A hosted multi-tenant service is not a product target, and optional host integrations remain consumers of the same local core.

Supported jobs are installed-document inventory, exact identifier lookup, record evidence retrieval, lexical discovery, scoped exhaustive traversal, conservative exact-identity edition comparison, evidence packet assembly, one-record source-first reader and neutral engineering handoff export, official-source verification, deterministic PDF and corpus compilation, unreviewed outline derivation, reviewed structural compilation, bounded reviewed semantic packet compilation, guided local model use, offline synthetic contract qualification, non-mutating local readiness diagnosis, and deterministic release-evidence verification. The implemented baseline includes strict pack validation, policy-bound installation, seven deterministic read operations, a principal-bound stdio MCP adapter with operation-specific output schemas, detailed/compact/concise responses, request-local integrity verification, bounded authorization-safe caches, compressed pack transport, explicit representation selection, a content-bound fictional benchmark that preserves raw results and exact release-gate arithmetic, a closed doctor report that proves one policy-scoped exact query without initializing or migrating state, a deterministic no-script handoff that preserves the detailed packet while keeping caller interpretation and host decisions separate, release sidecars that keep unsigned local consistency separate from CI-signed identity, and a resource-limited parser process boundary shared by page, corpus, and reviewed-structure compilation. Document inventory and near-match hints are filtered by current principal grants, exact or prefix-based rather than fuzzy, and never select a project baseline. Structural required edges must agree with retrieval dependencies; edition comparison keeps non-authoritative alignment candidates separate and traverses before/after dependency graphs independently; page, derived, and reviewed evidence are bound to exact UTF-8 sidecar offsets; semantic review remains distinct from applicability and approval; parser failure is distinct from a no-text page and prevents complete-corpus claims; mixed public/restricted component sets remain explicitly incomplete; and CI validates schema metaschemas, concrete contract instances, actual response packets and handoffs, malformed negative cases, the offline synthetic benchmark, an installed dependency-free core wheel, the actual extracted starter, and its deterministic release evidence across Windows and Linux on Python 3.11 and 3.12.

The text layer of real PDFs is compiled into page records through a disposable parser worker, a separate deterministic pass emits unreviewed outline candidates and explicit unsupported regions, and one explicitly reviewed section is compiled into structural nodes and relationships. The worker rechecks source bytes after OS limits are installed, writes bounded per-page UTF-8 files, and activates a canonical result last; the parent streams accepted files into established sidecar formats. A synthetic acceptance packet proves one reviewed multi-page semantic requirement plus exact governing note, definition, and transitive table context; it is not a real-corpus or document-wide coverage claim. The benchmark qualifies its runner and fictional contract behavior, including edition isolation, citations, required context, and false-completeness checks. It does not measure real-document discovery accuracy, semantic fidelity, tokenizer-normalized efficiency, largest-document resource suitability, or engineer time. No document-wide runtime claim is made for visual fidelity, OCR, reviewed semantic clause segmentation, table-cell or figure-visual interpretation, obligation classification, applicability, HTTP serving, catalog synchronization, certification, or controlled workloads. Hosted-service and tenant-isolation requirements from the supplied PRD are out of scope for this local distribution model. Numerical real-document quality targets in the supplied PRD remain unmeasured release targets.

## Invariants

1. Preserve original source bytes, original and normalized identifiers, edition composition, conditions, exceptions, and unsupported regions.
2. Keep source facts, derived records, deterministic checks, and human approval separate.
3. Do not treat catalog currentness as a project baseline or candidate relevance as applicability.
4. Do not satisfy exhaustive retrieval with top-k search.
5. Do not omit required evidence to fit a budget while marking the packet complete.
6. Do not grant access from pack-supplied rights claims.
7. Do not make query paths fetch, import, activate, publish, or execute content.

The machine-readable acceptance subset for the implemented slice is in `docs/requirements/requirements.json`.
